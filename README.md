# MECS6616 Spring 2026 Assignment 3

This repository contains my submission for Assignment 3 in `MECS6616`, focused on two related but distinct control problems:

1. Diffusion-policy behavioral cloning on the PushT manipulation task
2. Reinforcement learning with PPO on the HalfCheetah task

The main deliverable is the notebook `mecs6616_Spring2026_Assignment3_di2256.ipynb`, which was developed and run in Google Colab. The repository also includes the saved model checkpoints and video artifacts generated or collected during evaluation.

## Project Overview

The assignment is split into two parts.

### Part 1: Diffusion Policy for PushT

The PushT task is a 2D manipulation environment where an agent must push a T-shaped object toward a goal pose. The notebook uses demonstration data and implements the key parts of a Denoising Diffusion Probabilistic Model (DDPM) for behavioral cloning.

The implemented work includes:

- Cosine beta schedule
- Forward diffusion process
- Reverse denoising process
- Diffusion-policy training loop
- Diffusion-policy inference loop
- Single-episode and multi-episode evaluation rollouts

The notebook evaluates the diffusion policy using receding-horizon control:

- Observation horizon: `2`
- Predicted action horizon: `16`
- Executed action horizon per replan: `8`

### Part 2: Reinforcement Learning on HalfCheetah

The second part switches from imitation learning to reinforcement learning because PushT is not well suited to vanilla RL due to sparse rewards and constrained action dynamics.

For this part, the notebook:

- Uses a provided `dm_control` to Gym wrapper
- Creates vectorized environments for Stable-Baselines3
- Trains a PPO policy
- Saves the trained PPO checkpoint
- Runs a manual visualization rollout

## Implemented Components

### DDPM Components

The notebook implements the missing logic for the diffusion-policy section, including:

- `cosine_beta_schedule(...)`
- `DDPM.__init__(...)`
- `DDPM.diffuse(...)`
- `DDPM.denoise(...)`
- diffusion training loss computation
- `ddpm_inference(...)`

Conceptually, the workflow is:

1. Normalize PushT observations and action sequences from the dataset
2. Sample Gaussian noise and random timesteps
3. Diffuse clean actions into noisy actions
4. Train the network to predict the added noise
5. Use reverse denoising at inference time to generate action sequences
6. Execute the first portion of each predicted action horizon in a receding-horizon loop

### PPO Training

The RL section instantiates a PPO agent with Stable-Baselines3 and trains it on the provided vectorized HalfCheetah environment.

The implemented training block:

- creates the vectorized environment with `make_vec_env(...)`
- defines PPO policy architecture and hyperparameters
- trains for `500000` timesteps
- saves the policy to `rl_policy.zip`

## Videos and How They Were Generated

The `videos/` directory is organized by provenance rather than by task alone.

### `videos/outputs/ddpm_vis.mp4`

This is a single PushT evaluation rollout from the trained diffusion policy.

It is generated by the notebook cell that:

- loads `diffusion_policy.pth`
- runs `ddpm_inference(...)`
- executes actions in the PushT environment
- collects frames with `env.render(mode='rgb_array')`
- saves them with:

```python
vwrite('ddpm_vis.mp4', imgs)
```

### `videos/outputs/ddpm_combined_vis.mp4`

This is a combined PushT evaluation video across multiple seeded episodes.

It is generated by the notebook cell that:

- loops through `10` evaluation episodes
- runs the trained diffusion policy each time
- appends all rendered frames to a shared list
- saves the result with:

```python
vwrite('ddpm_combined_vis.mp4', combined_imgs)
```

### `videos/demos/demo_vis.mp4`

This is not a trained-policy output. It is a replay of demonstration data from the PushT dataset.

It is produced by the notebook cell that:

- pulls normalized observations/actions from the dataloader
- unnormalizes them
- resets the environment to demonstration states
- replays demonstration actions
- saves the frames with:

```python
vwrite('demo_vis.mp4', demo_imgs, inputdict={'-r': '10'})
```

### `videos/manual/cheetah.mp4`

This file corresponds to the manual HalfCheetah visualization but was manually downloaded rather than written directly by the saved notebook source.

In the notebook, the RL visualization cell:

- loads `rl_policy.zip`
- runs one evaluation rollout in the wrapped HalfCheetah environment
- records frames using the environment log
- displays the result inline with:

```python
show_video(frames, fps=25)
```

The saved notebook shows inline playback, not an explicit `vwrite('cheetah.mp4', ...)` call, so this repository stores that file separately under `videos/manual/`.
